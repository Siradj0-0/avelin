# Release checks and update security

Avelin's checker is advisory: it requests only GitHub release metadata and never downloads, installs, or executes release assets. The UI opens the fixed repository releases page, not a URL supplied in release metadata. A release notification is **not** proof that a package is available, compatible, authentic, or safe. Check the publisher and the provenance of anything you install. There is no signature, artifact digest, or package-origin verification in the checker.

## What the check means

The GitHub REST [list releases](https://docs.github.com/en/rest/releases/releases#list-releases) endpoint returns releases, not every Git tag. The checker requests one page of at most 30 releases, caps the response at 1,000,000 bytes, and uses an eight-second network-operation timeout. It makes no automatic retries. GitHub can return rate-limit errors; wait before trying again, following [GitHub's guidance](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api#rate-limit-errors). Checks are unauthenticated and share the network's unauthenticated API limit.

Only tags of the form `vMAJOR.MINOR.PATCH` or `MAJOR.MINOR.PATCH` (ASCII digits, no leading zeroes, at most 64 characters) are compared as numeric triples. Suffixes, build metadata and distro package versions are not understood; this is not full SemVer, PEP 440 or Debian version comparison. Drafts are excluded. For compatibility with the existing behavior, releases marked as prereleases **are included** when their tags are numeric; notifications explicitly identify a prerelease. A suffix such as `-rc1` is ignored. The highest comparable version on the fetched page is reported if it exceeds the app's embedded version. GitHub's [latest release endpoint](https://docs.github.com/en/rest/releases/releases#get-the-latest-release) has different selection semantics, so this checker does not use it.

A full 30-item page, or an unexpected entry, makes a negative result inconclusive rather than claiming the app is current. A positive result only proves that a newer comparable tag appeared in the fetched page, not that it is the newest. Empty or unsupported-tag-only pages yield no numbered releases, not a security guarantee. Invalid data, network errors and rate limits produce errors. The limit and timeout do not provide a strict wall-clock deadline against a slow peer; redirects are accepted only to HTTPS on `api.github.com` (default HTTPS port or 443), with no URL credentials; rejected or malformed redirects make the check unavailable. Standard redirect-loop limits still apply. Network proxies and their trust configuration remain outside this restriction. The UI can trigger concurrent checks, and no cache or backoff is implemented.

## Updating safely

Use the trusted channel that installed Avelin, and follow that channel's package-specific instructions. For a distribution-managed package, use the distribution's configured package manager and repositories; a GitHub release may not yet be packaged and its version may not match the distro package version. Avoid replacing distro-managed files with a manual install. The repository's experimental local Debian package uses a `~dev1` package version while the embedded app version lacks that suffix, so the checker cannot determine whether that particular package is current. The local .deb build and installation instructions are in [packaging.md](packaging.md); it is not a published update channel.

For a manual source or release installation, independently verify the project, release provenance and any signatures or checksums through a trusted channel before following reviewed instructions. A checksum obtained from the same compromised source as an artifact alone does not establish authenticity. If a Python package is ever distributed through pip, [pip's secure-install guidance](https://pip.pypa.io/en/stable/topics/secure-installs/) describes pinned requirements with independently trusted hashes and `--require-hashes`; this is not a claim that Avelin is currently published on PyPI. Do not pipe a remote script into a shell or run an unfamiliar binary just because an update notification appeared.
