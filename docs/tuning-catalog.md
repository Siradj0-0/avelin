# Informational tuning catalog

`avelin.tuning_catalog.catalog()` returns a small, immutable set of descriptions of GNOME animations, zram and system power profiles. This is a **static information prototype**, not a feature recommendation, capability detector, benchmark or action API. Entries do not establish that the current system supports a setting or that Avelin provides a control for it. It is not connected to the UI or optimizer.

The catalog reads no files, environment, desktop settings, kernel state or network and does not run commands or modify the system. The source links document the underlying mechanisms, not the current machine's state. The entries deliberately do not suggest parameter values or promise an improvement. Performance and accessibility effects depend on the workload, hardware and desktop.

- GNOME's [`enable-animations` schema](https://gitlab.gnome.org/GNOME/gsettings-desktop-schemas/-/raw/main/schemas/org.gnome.desktop.interface.gschema.xml.in) describes a global desktop-interface preference. Restoring a previous configuration requires distinguishing an explicit user override from the absence of one; see [get_user_value](https://docs.gtk.org/gio/method.Settings.get_user_value.html) and [reset](https://docs.gtk.org/gio/method.Settings.reset.html).
- The [kernel zram documentation](https://docs.kernel.org/admin-guide/blockdev/zram.html) describes RAM-backed compressed block devices, their uses and reset behavior. zram is not necessarily swap. Its presence alone does not establish hibernation readiness; [kernel hibernation documentation](https://docs.kernel.org/power/swsusp-and-swap-files.html) describes additional swap-file requirements. Restoring a configuration is not restoration of device data.
- The [power-profiles daemon API](https://upower.pages.freedesktop.org/power-profiles-daemon/gdbus-org.freedesktop.UPower.PowerProfiles.html) explains that changing the active profile releases held profiles. A hold check cannot prevent a new hold arriving before a change, and switching back cannot recreate a released hold. **Do not use the profile selector in the v0.1.0 prerelease**; see [issue #15](https://github.com/Siradj0-0/avelin/issues/15). A future integration must not treat the catalog as authorization to write.

The catalog is intentionally independent of the existing optimizer and undo-journal prototypes. It does not supply execution parameters, snapshots, permissions, rollback or host validation. Any future UI integration requires separate design and review, including current-version safety status and accessible presentation.
